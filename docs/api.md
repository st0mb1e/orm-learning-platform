# REST API

Примеры рассчитаны на стенд по адресу `http://localhost:8081/api`. Запросы с телом и ответы с данными используют JSON. Время передавайте в ISO 8601 со смещением, например `2026-12-01T23:59:00+03:00`. В ответах сервер возвращает время в UTC с суффиксом `Z`. Поле `enrolledAt` в записи на курс содержит только дату.

Сервер отвечает `201` при создании, `200` при чтении или изменении и `204` при удалении. За ошибку в запросе возвращает `400`, за отсутствующую запись — `404`, за дубль или конфликт — `409`. Попытка оценить работу на чужом курсе или изменить чужой отзыв даёт `403`.

На демостенде передавайте идентификатор участника в запросе. API проверяет правила сценария по этому идентификатору. Входа через сессию или токен в приложении нет.

## Пользователи и профили

| Метод и путь | Действие |
|---|---|
| `GET /users` | Получить список пользователей |
| `GET /users/{id}` | Получить пользователя по ID |
| `POST /users` | Создать пользователя |
| `PUT /users/{id}` | Изменить имя, email, роль |
| `DELETE /users/{id}` | Удалить пользователя и его учебные данные. Преподавателя можно удалить после передачи или удаления его курсов |
| `GET /users/{id}/profile` | Получить профиль |
| `PUT /users/{id}/profile` | Создать или обновить профиль |
| `DELETE /users/{id}/profile` | Удалить профиль |
| `GET /users/{id}/enrollments` | Записи студента на курсы, включая статусы |
| `GET /users/{id}/submissions` | Сданные работы и оценки |
| `GET /users/{id}/quiz-results` | Результаты тестов студента |

`POST /users` и `PUT /users/{id}` принимают одинаковые поля.

```json
{
  "name": "Новый студент",
  "email": "student@example.org",
  "role": "STUDENT"
}
```

В поле `role` можно передать `STUDENT`, `TEACHER` или `ADMIN`. Перед сохранением сервер приводит email к нижнему регистру. Роль можно поменять, пока у пользователя нет курсов, записей, работ, результатов тестов и отзывов.

Например, в `PUT /users/{id}/profile` можно передать биографию и оставить ссылку на аватар пустой.

```json
{
  "bio": "Изучаю Java и PostgreSQL",
  "avatarUrl": null
}
```

## Категории и теги

| Метод и путь | Действие |
|---|---|
| `GET /categories`, `GET /tags` | Список |
| `POST /categories`, `POST /tags` | Создать |
| `PUT /categories/{id}`, `PUT /tags/{id}` | Переименовать |
| `DELETE /categories/{id}`, `DELETE /tags/{id}` | Удалить, если не используются курсами |

Чтобы добавить или переименовать категорию либо тег, передайте название в поле `name`, например `{"name": "Java"}`. Сервер вернёт `id` и `name`.

## Курсы и запись студентов

| Метод и путь | Действие |
|---|---|
| `GET /courses` | Страница курсов |
| `GET /courses/{id}` | Курс, теги, модули, уроки и задания |
| `POST /courses` | Создать курс |
| `PUT /courses/{id}` | Изменить курс, преподавателя, категорию и теги |
| `DELETE /courses/{id}` | Удалить курс и все зависимые учебные данные |
| `POST /courses/{id}/enrollments` | Записать студента |
| `GET /courses/{id}/students` | Активные студенты курса |
| `DELETE /courses/{id}/students/{studentId}` | Отписать студента |
| `PATCH /enrollments/{id}` | Изменить статус записи |

В `GET /courses` можно искать по названию через `search` и отбирать курсы по `categoryId` или `teacherId`. Номер страницы `page` начинается с 0. Параметр `size` принимает значения от 1 до 100, по умолчанию возвращается до 10 курсов. Курсы отсортированы по `id`.

При поиске по названию `GET /courses?search=Hibernate` вернёт страницу подходящих курсов.

```json
{
  "content": [
    {
      "id": 1,
      "title": "Основы Hibernate",
      "description": "Работа с ORM",
      "teacherId": 1,
      "teacherName": "Ведущий курса",
      "categoryId": 1,
      "categoryName": "Программирование"
    }
  ],
  "page": 0,
  "size": 10,
  "totalElements": 1,
  "totalPages": 1
}
```

При создании и изменении курса передайте название, описание, преподавателя, категорию и список тегов.

```json
{
  "title": "Основы Hibernate",
  "description": "Работа с ORM",
  "teacherId": 1,
  "categoryId": 1,
  "tagIds": [1, 2]
}
```

У пользователя из `teacherId` должна быть роль `TEACHER`. Если у курса нет тегов, передайте пустой массив `"tagIds": []`. В ответе на `GET /courses/{id}` основные поля лежат в объекте `course`, теги и модули — в отдельных массивах `tags` и `modules`.

Для записи на курс передайте `{"studentId": 3}`. Чтобы поменять статус, отправьте, например, `{"status": "COMPLETED"}`. Разрешены `ACTIVE`, `COMPLETED` и `CANCELLED`. Сдать работу или пройти тест можно со статусом `ACTIVE`. При отписке сервер удаляет запись на курс. Работы и результаты студента остаются в базе.

## Модули, уроки и задания

| Метод и путь | Действие |
|---|---|
| `POST /courses/{id}/modules` | Создать модуль |
| `GET /modules/{id}` | Модуль с уроками |
| `PUT /modules/{id}` | Изменить модуль |
| `DELETE /modules/{id}` | Удалить модуль и содержимое |
| `POST /modules/{id}/lessons` | Создать урок |
| `GET /lessons/{id}` | Урок и задания |
| `PUT /lessons/{id}` | Изменить урок |
| `DELETE /lessons/{id}` | Удалить урок и задания |
| `POST /lessons/{id}/assignments` | Создать задание |
| `GET /assignments/{id}` | Задание |
| `PUT /assignments/{id}` | Изменить задание |
| `DELETE /assignments/{id}` | Удалить задание и решения |

У модуля есть название и номер внутри курса.

```json
{
  "title": "Сущности и связи",
  "orderIndex": 1
}
```

Для урока укажите название, материал и номер внутри модуля. Ссылка на видео может быть пустой.

```json
{
  "title": "OneToMany",
  "content": "Материалы урока",
  "videoUrl": null,
  "orderIndex": 1
}
```

Номера начинаются с 1. В одном курсе номера модулей не повторяются, в одном модуле не повторяются номера уроков. При изменении передавайте те же поля, что и при создании.

В задании обязательны название, условие и максимальный балл. Срок сдачи можно указать в `dueDate`.

```json
{
  "title": "Модель курса",
  "description": "Опишите связь курса и модулей",
  "dueDate": "2026-12-01T23:59:00+03:00",
  "maxScore": 100
}
```

Для задания без срока передайте `"dueDate": null`. Максимальный балл задаётся целым числом от 1 до 1000. В браузере форма переводит выбранное местное время в UTC, поэтому срок не сдвигается при смене часового пояса сервера. О хранении времени подробнее в [описании модели](architecture.md#сущности).

## Решения и оценки

| Метод и путь | Действие |
|---|---|
| `POST /assignments/{id}/submissions` | Отправить решение |
| `GET /assignments/{id}/submissions` | Решения по заданию |
| `GET /submissions/{id}` | Решение с оценкой |
| `PATCH /submissions/{id}/grade` | Оценить или изменить оценку |

Чтобы сдать работу, передайте идентификатор студента и текст ответа в `POST /assignments/{id}/submissions`.

```json
{
  "studentId": 3,
  "content": "Внешний ключ course_id хранится в таблице модулей."
}
```

Студент может сдать одно решение на задание. При повторной отправке или после дедлайна сервер вернёт `409`.

В `PATCH /submissions/{id}/grade` передайте идентификатор преподавателя и балл. К оценке можно добавить комментарий.

```json
{
  "teacherId": 1,
  "score": 90,
  "feedback": "Верно, добавьте описание каскадного удаления."
}
```

В ответе есть идентификатор задания `assignmentId`, студент `studentId` и `studentName`, время отправки `submittedAt`, текст `content`, балл `score` и комментарий `feedback`. Пока работу не проверили, `score` равен `null`.

## Тесты

| Метод и путь | Действие |
|---|---|
| `POST /modules/{id}/quiz` | Создать тест модуля |
| `GET /quizzes/{id}` | Тест, вопросы и варианты без признака правильности |
| `PUT /quizzes/{id}` | Заменить содержание теста, если попыток ещё нет |
| `DELETE /quizzes/{id}` | Удалить тест, вопросы, варианты и результаты |
| `POST /quizzes/{id}/submissions` | Пройти тест |
| `GET /quizzes/{id}/submissions` | Результаты теста. Можно отфильтровать по `studentId` |

При создании или обновлении теста передайте вопросы и отметьте правильные варианты.

```json
{
  "title": "Связи JPA",
  "questions": [
    {
      "text": "Где хранится внешний ключ?",
      "type": "SINGLE_CHOICE",
      "options": [
        {"text": "На стороне Many", "correct": true},
        {"text": "На стороне One", "correct": false}
      ]
    }
  ]
}
```

Вопрос может быть с одиночным (`SINGLE_CHOICE`) или множественным выбором (`MULTIPLE_CHOICE`). Добавьте от 1 до 100 вопросов и от 2 до 10 вариантов на вопрос. Сервер вернёт идентификаторы вопросов и вариантов при создании теста. Они понадобятся для отправки попытки.

```json
{
  "studentId": 3,
  "answers": [
    {"questionId": 1, "optionIds": [1]}
  ]
}
```

В ответе сервер возвращает результат попытки.

```json
{
  "id": 1,
  "quizId": 1,
  "studentId": 3,
  "score": 100,
  "takenAt": "2026-11-14T20:30:00Z"
}
```

Пропущенный вопрос не засчитывается. Сервер вернёт `400`, если вопрос не входит в тест, вариант относится к другому вопросу, один вопрос повторяется в запросе или для одиночного выбора указано несколько вариантов. Тест можно пройти снова. Сервер сохранит каждую попытку отдельно.

## Отзывы

| Метод и путь | Действие |
|---|---|
| `GET /courses/{id}/reviews` | Отзывы курса |
| `POST /courses/{id}/reviews` | Создать отзыв |
| `PUT /reviews/{id}` | Изменить отзыв автора |
| `DELETE /reviews/{id}` | Удалить отзыв |

Отзыв может оставить студент с активной или завершённой записью. На один курс разрешён один отзыв с оценкой от 1 до 5.

```json
{
  "studentId": 3,
  "rating": 5,
  "comment": "Понятные примеры связей"
}
```

## Формат ошибки

```json
{
  "status": 409,
  "message": "Студент уже записан на курс",
  "details": [],
  "timestamp": "2026-11-14T20:30:00Z"
}
```

При ошибке валидации в `details` перечислены поля и причины, по которым они не прошли проверку. Если в JSON есть неизвестное поле, сервер отклонит запрос.
