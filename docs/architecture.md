# Модель данных и устройство приложения

## Сущности

В модели 15 сущностей. Они наследуют идентификатор и поле версии от `BaseEntity`. Идентификатор генерируется при сохранении, а версия нужна для оптимистической блокировки. У `BaseEntity` стоит `@MappedSuperclass`, поэтому своей таблицы у него нет.

| Класс | Таблица | Назначение и связи |
|---|---|---|
| `User` | `users` | Имя, уникальный email и роль. Преподаватель ведёт курсы. У студента есть записи на курсы, работы, результаты и отзывы |
| `Profile` | `profiles` | Биография и аватар. У пользователя может быть один профиль (`OneToOne`) |
| `Category` | `categories` | Название категории. К ней можно отнести несколько курсов |
| `Course` | `courses` | Название и описание, преподаватель, категория, модули, записи студентов, отзывы и теги |
| `Enrollment` | `enrollments` | Дата и статус записи на курс. Пара `student_id` и `course_id` уникальна |
| `CourseModule` | `course_modules` | Порядковый номер модуля в курсе, его уроки и необязательный тест |
| `Lesson` | `lessons` | Материалы, ссылка на видео и задания урока |
| `Assignment` | `assignments` | Условие задания, срок сдачи и максимальный балл |
| `Submission` | `submissions` | Решение студента, время сдачи, оценка и комментарий. У студента одно решение на задание |
| `Quiz` | `quizzes` | Вопросы и результаты теста. У модуля может быть один тест (`OneToOne`) |
| `Question` | `questions` | Вопрос теста с одиночным или множественным выбором |
| `AnswerOption` | `answer_options` | Текст варианта и признак правильности, ссылка на вопрос |
| `QuizSubmission` | `quiz_submissions` | Студент, тест, процент верных ответов и время попытки |
| `CourseReview` | `course_reviews` | Оценка, комментарий и дата. Студент может оставить один отзыв на курс |
| `Tag` | `tags` | Метка, которую можно добавить к нескольким курсам. Связь `ManyToMany` хранится в `course_tags` |

`CourseModule` назван так, чтобы не путать учебный модуль с `java.lang.Module`.

Сроки сдачи, время отправки работ, попыток теста и отзывов в Java имеют тип `Instant`. PostgreSQL хранит их в столбцах `timestamp with time zone`. API возвращает время в UTC, а браузер показывает его в часовом поясе пользователя. Дедлайн остаётся тем же при запуске в контейнере с другим часовым поясом.

В курс можно добавить модули, в модуль — уроки, в урок — задания. Одно задание может собрать решения нескольких студентов. У теста есть вопросы, у вопроса есть варианты ответа. Во всех этих связях `OneToMany` внешний ключ хранится на стороне `ManyToOne`. Например, `course_modules.course_id` указывает на курс.

Для записи студента на курс нужна отдельная сущность `Enrollment`. В ней кроме двух внешних ключей есть дата и статус. Для связи курсов с тегами хватает таблицы `course_tags`, у которой нет отдельного JPA-класса.

## Загрузка данных

У всех связей явно указан `FetchType.LAZY`. Для коллекций это подтверждает отдельный интеграционный тест. На обратной стороне `OneToOne` Hibernate без bytecode enhancement всё равно может выполнить запрос, чтобы узнать, есть ли связанная запись.

В настройках стоит `spring.jpa.open-in-view=false`. Сервис собирает DTO внутри транзакции и возвращает его в контроллер. Когда Spring пишет JSON, сессия Hibernate уже закрыта и дополнительных запросов к базе для этого ответа нет.

`CourseRepository.findDetailedById` через `EntityGraph` загружает преподавателя, категорию и модули. За тегами и вложенными коллекциями сервис обращается отдельно. Если присоединить сразу несколько коллекций, число строк в SQL-ответе вырастет и модули могут повториться. Для пакетной подгрузки задано `default_batch_fetch_size=20`.

В списке курсов граф загружает преподавателя, его профиль и категорию. Коллекций в графе нет, поэтому PostgreSQL возвращает сразу нужную страницу. В тесте на страницу с разными преподавателями уходит до двух SQL-запросов. Первый получает строки, второй при необходимости считает подходящие курсы.

`LazyLoadingIntegrationTest` проверяет ленивую загрузку на трёх примерах.

1. Если обратиться к незагруженной коллекции после закрытия сессии, Hibernate выбросит `LazyInitializationException`.
2. Если заранее загрузить коллекцию через `EntityGraph`, её можно прочитать после завершения транзакции.
3. DTO с уроками и заданиями можно прочитать и после закрытия транзакции. В нём обычные данные, без прокси Hibernate.

## Правила удаления

- Вместе с курсом удаляются модули, уроки, задания, работы, тесты, результаты, записи студентов и отзывы. Интерфейс просит подтвердить удаление.
- Вместе со студентом удаляются его профиль, записи, работы, результаты и отзывы. Курсы и преподаватели остаются в базе.
- Перед удалением преподавателя нужно передать его курсы другому преподавателю или удалить их.
- Категории и теги могут использоваться в нескольких курсах. При удалении курса они остаются в базе. Удалить категорию или тег можно, когда они больше не используются.
- При отписке удаляется только `Enrollment`. Сданные работы и результаты тестов остаются у студента.
- Hibernate удаляет вопросы и варианты через `orphanRemoval`. Пока у теста есть хотя бы одна попытка, вопросы нельзя изменить. Так результат относится к той версии теста, которую проходил студент.

В сущностях Lombok генерирует методы доступа и пустые конструкторы. `@Data` здесь не используется. Сгенерированные им `toString`, `equals` и `hashCode` могли бы обратиться к ленивым связям и зациклиться на двусторонней связи.

## Сервисные модули

| Сервис | Что делает |
|---|---|
| `UserService` | Управляет пользователями и профилями, приводит email к нижнему регистру, проверяет смену роли |
| `ReferenceService` | Управляет категориями и тегами, проверяет уникальность названий и использование перед удалением |
| `CourseService` | Управляет курсами, назначает преподавателя, категорию и теги. Возвращает список курсов с фильтрами или полную структуру одного курса |
| `ContentService` | Управляет модулями, уроками и заданиями. Учитывает порядок материалов и проверяет новый максимальный балл |
| `EnrollmentService` | Записывает и отписывает студентов, меняет статус записи, возвращает списки студентов и курсов. Проверяет наличие активной записи |
| `SubmissionService` | Принимает одно решение до дедлайна, возвращает решения и сохраняет оценку |
| `QuizService` | Создаёт и редактирует тесты, принимает попытки и сохраняет результаты |
| `QuizGrader` | Проверяет выбранные варианты и считает процент правильных ответов без обращения к базе |
| `ReviewService` | Принимает по одному отзыву от студента на курс и проверяет автора при редактировании |
| `ViewMapper` | Собирает DTO из сущностей внутри транзакции сервиса |

Для чтения сервисы используют `@Transactional(readOnly = true)`. Методы, которые меняют данные, открывают обычную транзакцию. `@Valid` проверяет входные DTO в контроллерах. На сервисах с `@Validated` проверка срабатывает и при прямом вызове метода через Spring.

При одиночном выборе нужен ровно один правильный вариант, при множественном — хотя бы один. Чтобы вопрос засчитался, студент должен отметить все правильные варианты. Лишний вариант или пропуск делает ответ неверным. Процент правильных ответов округляется до целого числа. Тест можно пройти повторно, каждая попытка хранится отдельно.

Работу оценивает преподаватель соответствующего курса. Балл находится в диапазоне от нуля до максимума задания. Уменьшить максимум ниже уже выставленной оценки нельзя.

## Остальные слои

`repository` содержит 15 интерфейсов `JpaRepository`. Для списков нужные связи подгружаются через `EntityGraph`. Поиск курсов использует `Specification` и экранирует `%` и `_`, чтобы они воспринимались как обычные символы.

В `web` отдельные контроллеры для пользователей, курсов, контента, тестов и справочников. `ApiExceptionHandler` возвращает код, сообщение и подробности в JSON. SQL и стек вызовов остаются на сервере. Ограничения уникальности в базе работают и при одновременных запросах. Если база отклонит дубль, API вернёт `409`.

В `dto` хранятся отдельные типы для запросов и ответов. При создании теста вариант ответа приходит как `OptionData` с полем `correct`. Студент получает `OptionView` с текстом и идентификатором варианта.

`config/DemoData` запускается в профиле `dev`, если таблица пользователей пуста. Данные создаются через те же сервисы, что вызывают REST-контроллеры. В профиле `test` каждый тест сам готовит нужные записи.

`static` содержит HTML, CSS и JavaScript без внешних библиотек. Формы отправляют запросы в REST API. Прежде чем вставить пользовательский текст в HTML, JavaScript экранирует его.
